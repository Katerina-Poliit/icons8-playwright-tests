# icons8-playwright-tests

E2E-тесты поиска и страницы иконки на https://icons8.com/icons
(Playwright + TypeScript, Page Object).

## Требования
- Node.js 20+
- Установленный Google Chrome (тесты идут в обычном Chrome с окном)

## Установка и запуск с нуля
```bash
git clone <URL репозитория>
cd icons8-playwright-tests
npm ci
npx playwright install chrome   # если Chrome не установлен
npm test                        # прогон (workers: 2)
npm run report                  # открыть HTML-отчёт
```
Если сайт покажет проверку «вы не робот», пройдите её руками в том же окне.

## Структура
- `pages/` — Page Object (`BasePage`, `SearchPage`, `IconPage`)
- `tests/` — тесты (`search.spec.ts`, `icon.spec.ts`)
- `playwright.config.ts` — конфиг (workers: 2, Chrome с окном, trace всегда)
- `.github/workflows/playwright.yml` — прогон на каждый push, отчёт артефактом
- `playwright-report/`, `test-results/` — HTML-отчёт и trace последнего локального прогона
- `AI_LOG.md` — как использовался ИИ

## Принципы
Локаторы по роли/тексту/атрибутам, без фиксированных пауз, тесты независимы
и не зависят от конкретных иконок. Баннер cookie закрывается через `addLocatorHandler`.

icons8-playwright-tests

E2E-тесты поиска и страницы иконки на https://icons8.com/icons (Playwright + TypeScript, Page Object). Тестовое задание, часть Б.

О видимости репозитория: он публичный, это согласовано с компанией. Подробности в документе с частями А и В.

Требования
Node.js 20+
Установленный Google Chrome (тесты идут в обычном Chrome с окном, не headless)
Установка и запуск с нуля
bash
git clone https://github.com/Katerina-Poliit/icons8-playwright-tests.git
cd icons8-playwright-tests
npm ci
npx playwright install chrome   # если Chrome не установлен
npm test                        # прогон, workers: 2
npm run report                  # открыть HTML-отчёт

Если сайт покажет проверку «вы не робот», нужно пройти её руками в том же окне. Тесты не нужно запускать в цикле: сайт боевой.

Структура
pages/: Page Object (BasePage, SearchPage, IconPage)
tests/search.spec.ts: поиск «cat», бессмысленный запрос, фильтр Filled
tests/icon.spec.ts: клик по иконке из выдачи
tests/cookie-banner.spec.ts: проверка обработчика cookie-баннера на имитации баннера
tests/download.spec.ts: скачивание гостем бесплатного PNG статичной иконки (тег @download)
playwright.config.ts: workers: 2, Chrome с окном, trace: 'on', локаль en-US
.github/workflows/playwright.yml: прогон на каждый push (без теста @download), HTML-отчёт сохраняется артефактом
playwright-report/, test-results/: HTML-отчёт и trace последнего локального прогона
AI_LOG.md: как использовался ИИ
Что покрыто тестами
Тест	Что проверяет
Поиск «cat»	после ввода и Enter адрес содержит /cat, заголовок H1 содержит «cat», иконки в выдаче видны
Иконка из выдачи	после клика по первой иконке видны превью, название иконки и кнопка скачивания
Бессмысленный запрос	запрос qzxwvjkplm приводит на страницу «ничего не найдено»: виден блок search-nothing-found, его заголовок содержит запрос
Фильтр Technique → Filled	адрес меняется на .../cat--technique-filled, число результатов уменьшается и остаётся больше нуля; повторное нажатие снимает фильтр, адрес и число результатов возвращаются. Из блоков левой панели выбран Technique как ближайший к понятию «стиль»
Обработчик cookie-баннера	на имитации баннера без обращения к сайту: баннер перекрывает кнопку, обработчик закрывает его, клик по кнопке проходит
Скачивание PNG (@download)	гость включает фильтр Static, открывает первую иконку, в окне скачивания (по умолчанию PNG и 48×48, оба Free) нажимает Download; имя файла оканчивается на .png, размер больше нуля, первые байты совпадают с сигнатурой PNG
Принципы
Локаторы по роли, тексту и атрибутам, без классов с хешем из сборки
Без фиксированных пауз (waitForTimeout нигде не используется)
Тесты независимы друг от друга и не зависят от конкретных иконок в выдаче
Предусловие во всех тестах: интерфейс на английском (проверка lang у <html> в BasePage.open)
Проблемы, с которыми столкнулась, и что с ними сделала
Приватный репозиторий недоступен. GitHub отключил приватные репозитории для моего аккаунта из-за региональных ограничений. Репозиторий публичный с согласия компании, после отбора будет удалён.
Сайт открывался как icons8.ru на русском в моём обычном Chrome. Playwright открывает чистый профиль и получает icons8.com на английском (<html lang="en">). Чтобы тесты не зависели от языка, в конфиге задана локаль en-US, а BasePage.open проверяет lang и падает сразу с понятной причиной. Локаторы построены на атрибутах и ролях, а не на русском тексте.
Поле поиска теряет введённый текст. В первом падении теста «cat» адрес оставался /icons после ввода и Enter. По trace видно: fill проходит, значение в поле есть, после Enter поиск не срабатывает, а на снимке страницы поле пустое. Вероятно, страница сбрасывает поле после догрузки скриптов, но причина не установлена. Обходной путь: SearchPage.search повторяет ввод через expect(...).toPass(), пока адрес не изменится. Это лечит симптом, а не причину. В части А я вынесла это как кандидат в баги или вопросы к продукту.
Выдача грузится несколько секунд (серые заглушки). Один из локальных прогонов упал, текст ошибки я не сохранила, поэтому причину назвать не могу. Ожидание первой иконки увеличено до 20 секунд, после этого прогоны были зелёными.
Клик по иконке не открывает отдельную страницу. Адрес остаётся /icons/set/cat, под выдачей раскрывается панель с превью, названием и кнопкой скачивания. Название иконки в панели — ссылка, а не h1 (h1 на странице всегда «Cat icons»). Моя первая версия проверки названия через h1 была ложной: она проходила и без клика. Сейчас название берётся из alt превью, поэтому тест не зависит от конкретной иконки. Кнопка скачивания ищется по атрибуту data-accordion-btn--download, а не по тексту. Кнопку тест только проверяет и не нажимает.
Баннер cookie ни разу не появился ни в локальных прогонах, ни в CI. Обработчик через addLocatorHandler на реальном баннере не проверен. Его логику проверяет отдельный тест cookie-banner.spec.ts на имитации баннера, которая перекрывает страницу (без обращения к сайту). Первая версия регулярного выражения была слишком широкой (ok совпало бы со словами cookie и book), я сузила её до точных названий кнопок. Обработчик регистрируется один раз на страницу.
Окно перевода Google Translate поверх страницы в Chrome. Тестам не мешает. Попытка убрать его флагами запуска не сработала и была удалена.
Первая версия проверки пустого результата была слабой. Она проверяла, что иконок в выдаче нет, и могла пройти, пока страница ещё грузилась. Страница «ничего не найдено» имеет собственный блок, и теперь тест ждёт именно его. Блок найден по CSS-классу search-nothing-found: у него нет роли и data-test, так что это самая хрупкая часть локаторов.
Фильтр. Кнопка Filled в дереве доступности называется «logo Filled» (слово из подписи значка), поэтому ищу её по слову Filled, а не по полному имени. Число результатов при смене фильтра обновляется с задержкой, поэтому тест ждёт его через expect.poll.
GitHub Actions. Запуск #1 красный (первая версия кода до исправления локаторов), запуск #2 зелёный (49 с), артефакт playwright-report сохраняется. Блокировки защитой от ботов в CI не наблюдалось, но по паре прогонов делать вывод рано. Тесты в CI идут с окном через xvfb-run.
Скачивание и лимит гостя. Тест скачивания тратит лимит скачиваний гостя при каждом запуске, а GitHub Actions гоняет тесты на каждый push. Поэтому тест помечен @download и исключён из CI (--grep-invert @download), там идут остальные 5 тестов. Локально он входит в обычный npm test. Файл сохраняется во временную папку и удаляется, в репозиторий он не попадает. Кнопки платных вариантов, «Free for a link» и «Edit in Lunacy» тест не нажимает. Статичность иконки обеспечивает фильтр Static. Ограничение: тест рассчитывает, что в окне по умолчанию выбраны бесплатные PNG и 48×48.
Результаты прогонов
Локально: три прогона подряд на финальном коде зелёные, 6 тестов из 6, ничего не пропущено (время каждого в HTML-отчёте). Перед ними один прогон на более ранней версии кода падал (см. п. 4).
GitHub Actions: запуск #1 красный, запуск #2 зелёный; результаты последних запусков во вкладке Actions.
Что не сделано или не проверено

Баннер cookie: обработчик проверен только на имитации баннера, на реальном не проверен (см. п. 6).
Причины двух событий не установлены: сброс поля поиска (п. 3) и один упавший локальный прогон (п. 4).
Хрупкое место: тест пустого результата опирается на CSS-класс блока (п. 8).
